# استاندارد رسمی افزودن اندیکاتور جدید

این سند مرجع توسعه اندیکاتورهای پروژه db-analytics است.
تمام اندیکاتورهای جدید باید از این استاندارد پیروی کنند.

## 1. ساختار فایل

هر اندیکاتور باید در یک فایل مستقل قرار گیرد:

    app/indicators/<indicator_name>.py

نمونه:

    app/indicators/rsi.py
    app/indicators/macd.py
    app/indicators/bollinger_bands.py

قواعد نام‌گذاری:
- نام فایل با حروف کوچک و underscore نوشته شود.
- شناسه اندیکاتور در metadata با نام ثابت و یکتا تعریف شود.
- نام فایل، کلاس و identifier تا حد ممکن هماهنگ باشند.
- منطق محاسباتی هر اندیکاتور در فایل مستقل باقی بماند.
- اندیکاتور نباید برای محاسبه به فایل اندیکاتور دیگری وابسته باشد؛
  مگر آنکه این وابستگی صریح، آزموده‌شده و مستند شده باشد.

## 2. قرارداد اجباری کلاس

هر اندیکاتور باید از کلاس زیر ارث‌بری کند:

    from app.indicators.base import (
        CandleInput,
        Indicator,
        IndicatorMetadata,
        IndicatorOutput,
    )

    class ExampleIndicator(Indicator):
        ...

کلاس باید این دو عضو را پیاده‌سازی کند:

1. property به نام metadata که یک IndicatorMetadata برگرداند.
2. متد calculate(candles, parameters) که دنباله‌ای از
   IndicatorOutput برگرداند.

هر دو عضو در کلاس پایه abstract هستند و حذف آن‌ها مجاز نیست.

## 3. استاندارد metadata

metadata باید تمام فیلدهای زیر را داشته باشد:

- identifier:
  شناسه یکتای اندیکاتور؛ برای مثال "rsi".
- display_name:
  نام خوانا؛ برای مثال "Relative Strength Index".
- implementation_version:
  نسخه پیاده‌سازی؛ برای مثال "1".
- description:
  توضیح روشن درباره فرمول و کاربرد اندیکاتور.
- default_parameters:
  دیکشنری پارامترها و مقادیر پیش‌فرض.
- required_lookback:
  حداقل تعداد کندل موردنیاز برای شروع محاسبه معتبر.

قواعد:
- identifier باید ثابت، یکتا و مناسب استفاده در API و دیتابیس باشد.
- تغییر فرمول به‌نحوی که نتایج قبلی را تغییر دهد باید با افزایش
  implementation_version همراه باشد.
- required_lookback باید با فرمول واقعی اندیکاتور سازگار باشد.
- مقادیر پیش‌فرض باید مستند و قابل استفاده باشند.
- نام کلیدهای خروجی باید ثابت و قابل پیش‌بینی باشند.

نمونه:

    @property
    def metadata(self) -> IndicatorMetadata:
        return IndicatorMetadata(
            identifier="example",
            display_name="Example Indicator",
            implementation_version="1",
            description="Description of the calculation.",
            default_parameters={"period": 14},
            required_lookback=14,
        )

مقدار required_lookback در این مثال صرفاً نمونه است؛
برای اندیکاتور واقعی باید بر اساس فرمول تعیین شود.

## 4. استاندارد پارامترها

در ابتدای calculate از اعتبارسنجی پایه استفاده شود:

    resolved = self.validate_parameters(parameters)
    period = resolved["period"]

متد validate_parameters در کلاس پایه:
- مقادیر پیش‌فرض را با پارامترهای ارسال‌شده ادغام می‌کند.
- پارامتر ناشناخته را رد می‌کند.
- نوع bool و انواع خارج از int، float و str را رد می‌کند.

این اعتبارسنجی عمومی کافی نیست. هر اندیکاتور باید محدودیت‌های
ویژه پارامترهای خود را نیز بررسی کند.

مثال برای period:

    if isinstance(period, bool) or not isinstance(period, int):
        raise ValueError("period must be an integer")
    if period < 1:
        raise ValueError("period must be positive")

قواعد:
- پارامتر ناشناخته نباید نادیده گرفته شود.
- مقدار نامعتبر باید با ValueError رد شود.
- پارامترهای عددی باید محدوده مشخص داشته باشند.
- مقدار bool نباید به‌عنوان عدد صحیح پذیرفته شود.
- تقسیم بر صفر، مقادیر NaN و بی‌نهایت باید مدیریت شوند.
- تمام پارامترهای پشتیبانی‌شده باید در default_parameters تعریف شوند.
- پارامترهای استفاده‌شده باید از resolved خوانده شوند.

## 5. استاندارد ورودی و خروجی

ورودی calculate از نوع Sequence[CandleInput] است.

فیلدهای CandleInput عبارت‌اند از:
- time: زمان کندل از نوع int
- open: قیمت بازشدن
- high: بیشترین قیمت
- low: کمترین قیمت
- close: قیمت بسته‌شدن
- tick_volume: حجم اختیاری

خروجی باید Sequence[IndicatorOutput] باشد.

هر IndicatorOutput شامل:
- time: زمان کندل
- values: نگاشت نام خروجی به float یا None

الگوی مورد انتظار:

    outputs.append(
        IndicatorOutput(
            time=candle.time,
            values={"example_value": value},
        )
    )

قواعد:
- برای هر کندل ورودی، دقیقاً یک خروجی متناظر تولید شود؛
  مگر اینکه قرارداد رسمی موتور پردازش تغییر کرده باشد.
- ترتیب خروجی باید با ترتیب کندل‌های ورودی یکسان باشد.
- زمان هر خروجی باید با زمان همان کندل ورودی برابر باشد.
- نام کلیدهای values باید ثابت باشد.
- مقادیر خروجی فقط float یا None باشند.
- برای دوره گرم‌شدن یا تاریخچه ناکافی از None استفاده شود.
- کندل ورودی نباید تغییر داده شود.
- تابع calculate نباید به API، شبکه یا سرویس خارجی وابسته باشد.
- برای ورودی خالی، خروجی خالی برگردانده شود.
- خطاهای پارامتر باید به‌صورت روشن گزارش شوند.
- رفتار ورودی‌های غیرعادی و تاریخچه ناکافی باید آزمون شود.

## 6. استاندارد محاسبات

هر اندیکاتور باید:
- فرمول مشخص و مستند داشته باشد.
- از ترتیب زمانی کندل‌ها پیروی کند.
- به کندل‌های آینده برای محاسبه مقدار گذشته دسترسی نداشته باشد؛
  مگر اینکه ماهیت اندیکاتور صریحاً چنین رفتاری را تعریف کند.
- دوره warm-up را درست مدیریت کند.
- در مرزهای محاسباتی، تقسیم بر صفر و تاریخچه ناکافی رفتار مشخص داشته باشد.
- از تغییر ناخواسته نتایج به علت نوع داده یا گردکردن جلوگیری کند.
- برای ورودی یکسان و پارامتر یکسان، خروجی تکرارپذیر داشته باشد.

اگر فرمول از مقادیر قبلی استفاده می‌کند، رفتار اولین مقادیر معتبر
و مقداردهی اولیه باید مستند شود.

## 7. ثبت در رجیستری و بارگذاری زمان اجرا

فایل app/indicators/registry.py تابع register_indicator را فراهم می‌کند.
این تابع:
- metadata را ثبت یا به‌روزرسانی می‌کند.
- پارامترها را اعتبارسنجی می‌کند.
- مجموعه پارامترها را با هش ذخیره می‌کند.
- در صورت وجود مجموعه پارامتر یکسان، از ثبت تکراری آن جلوگیری می‌کند.

نکته مهم:
register_indicator به‌تنهایی کلاس پایتون را کشف یا بارگذاری نمی‌کند.

برای هر اندیکاتور جدید، دو مرحله باید تأیید شود:

1. پیاده‌سازی اندیکاتور در مسیر مورداعتماد برنامه وارد و نمونه‌سازی شود.
2. اندیکاتور با سازوکار رسمی راه‌اندازی برنامه ثبت شود و در کاتالوگ
   API قابل مشاهده باشد.

بارگذاری پویای فایل‌های ناشناس یا اجرای کد دلخواه مجاز نیست.
اندیکاتورها باید صریحاً مورداعتماد و از مسیر رسمی برنامه ثبت شوند.

هنگام افزودن اندیکاتور:
- از مسیر ثبت و بارگذاری موجود پروژه استفاده کنید.
- اگر فهرست اندیکاتورها صریح است، import و ثبت لازم را به همان
  نقطه رسمی اضافه کنید.
- ثبت را در مسیر راه‌اندازی برنامه انجام دهید، نه در هر درخواست API.
- ثبت مجدد باید مطابق قرارداد registry تکرارپذیر باشد.
- پس از تغییر کد، سرویس باید با نسخه جدید کد راه‌اندازی شود.
- پیش از فعال‌سازی، وجود identifier در کاتالوگ بررسی شود.

هر تغییری در سازوکار بارگذاری یا ثبت باید در همین سند به‌روزرسانی شود.

## 8. آزمون‌های اجباری

برای هر اندیکاتور فایل آزمون مستقلی اضافه شود؛ برای مثال:

    tests/indicators/test_rsi.py

حداقل آزمون‌ها:

1. محاسبه روی داده شناخته‌شده با نتیجه مورد انتظار.
2. تعداد خروجی برابر تعداد کندل‌های ورودی.
3. حفظ ترتیب و زمان کندل‌ها.
4. رفتار صحیح در تاریخچه ناکافی.
5. ورودی خالی.
6. پارامتر پیش‌فرض.
7. پارامتر معتبر سفارشی.
8. رد پارامتر ناشناخته.
9. رد مقدار صفر، منفی یا نوع نامعتبر در صورت ممنوع بودن.
10. مدیریت داده‌های مرزی، از جمله نبود تغییر قیمت یا نبود سود/زیان.
11. نبود NaN و بی‌نهایت در مقادیر خروجی.
12. تکرارپذیری نتایج.

اعداد مورد انتظار آزمون باید از محاسبه مستقل یا مثال مرجع
قابل‌بررسی به دست آمده باشند؛ آزمونی که فقط وجود خروجی را بررسی کند
برای صحت فرمول کافی نیست.

## 9. فعال‌سازی و پردازش تاریخی

پس از ثبت اندیکاتور:
- شناسه باید در کاتالوگ API دیده شود.
- ایجاد instance باید با شناسه و پارامترهای معتبر موفق باشد.
- شناسه نماد و بازه زمانی باید معتبر باشند.
- وضعیت پردازش تاریخی باید بررسی شود.
- خطای پردازش نباید نادیده گرفته شود.
- پس از اتمام تاریخچه، پردازش آنلاین نیز باید بررسی شود.
- راه‌اندازی مجدد سرویس نباید باعث ثبت تکراری یا خرابی وضعیت شود.

قبل از اعلام موفقیت، وضعیت واقعی instance و لاگ‌های مربوطه بررسی شود.

## 10. مشاهده خروجی

قبل از افزودن هر اندیکاتور باید مشخص باشد نتایج آن از کدام مسیر
رسمی API یا لایه ذخیره‌سازی قابل مشاهده‌اند.

برای مشاهده نتیجه:
1. ابتدا کاتالوگ اندیکاتورها را بررسی کنید.
2. instance را با پارامترهای موردنظر ایجاد کنید.
3. وضعیت تاریخی و آنلاین را بررسی کنید.
4. از endpoint رسمی نتایج یا ابزار رسمی مشاهده داده استفاده کنید.
5. زمان کندل، نام کلید خروجی و مقدار محاسبه‌شده را بررسی کنید.

مسیر endpoint نتایج نباید حدس زده یا در این سند جعل شود.
مسیر واقعی باید از قرارداد API موجود پروژه گرفته و در بخش
«مسیر مشاهده نتایج» در انتهای همین سند ثبت شود.

## 12. الگوی پیشنهادی برای اندیکاتور ساده

این کد یک قالب اولیه است؛ فرمول، نام خروجی و دوره lookback باید
برای اندیکاتور واقعی تغییر کنند.

    from __future__ import annotations

    from collections.abc import Mapping, Sequence
    from typing import Any

    from app.indicators.base import (
        CandleInput,
        Indicator,
        IndicatorMetadata,
        IndicatorOutput,
    )


    class ExampleIndicator(Indicator):
        @property
        def metadata(self) -> IndicatorMetadata:
            return IndicatorMetadata(
                identifier="example",
                display_name="Example Indicator",
                implementation_version="1",
                description="Replace with the actual formula.",
                default_parameters={"period": 3},
                required_lookback=3,
            )

        def calculate(
            self,
            candles: Sequence[CandleInput],
            parameters: Mapping[str, Any],
        ) -> Sequence[IndicatorOutput]:
            resolved = self.validate_parameters(parameters)
            period = resolved["period"]

            if isinstance(period, bool) or not isinstance(period, int):
                raise ValueError("period must be an integer")
            if period < 1:
                raise ValueError("period must be positive")

            closes: list[float] = []
            outputs: list[IndicatorOutput] = []

            for candle in candles:
                closes.append(float(candle.close))

                if len(closes) < period:
                    value = None
                else:
                    value = sum(closes[-period:]) / period

                outputs.append(
                    IndicatorOutput(
                        time=candle.time,
                        values={"example_value": value},
                    )
                )

            return outputs

این نمونه میانگین ساده قیمت بسته‌شدن را محاسبه می‌کند و صرفاً
برای نمایش قرارداد کدنویسی است؛ برای استفاده واقعی، شناسه و نام
خروجی را متناسب با فرمول انتخاب کنید.

## 13. مواردی که باید یک‌بار برای پروژه تکمیل شوند

برای اینکه توسعه‌دهنده در آینده مجبور به بررسی مجدد سرور نباشد،
این اطلاعات پروژه باید در همین سند تثبیت شوند:

- نقطه رسمی import و ثبت اندیکاتورها در زمان راه‌اندازی.
- دستور رسمی اجرای آزمون‌های پروژه.
- endpoint دقیق کاتالوگ اندیکاتورها.
- endpoint دقیق ایجاد و مشاهده instanceها.
- endpoint یا روش رسمی مشاهده مقادیر محاسبه‌شده.
- روش رسمی راه‌اندازی مجدد سرویس و مشاهده لاگ‌ها.

تا زمانی که این موارد با کد واقعی پروژه تطبیق داده نشده‌اند،
نباید مسیر یا دستور فرضی به‌عنوان قرارداد قطعی استفاده شود.
